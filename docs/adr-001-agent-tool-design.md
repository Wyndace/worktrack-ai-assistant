# ADR 001: Quality gate постановок WorkTrack и GigaChat API

**Статус:** Принято  
**Дата:** 2026-10-08  
**Команда:** БСБО-11-23  
**Проект:** WorkTrack AI Assistant

## Контекст

WorkTrack управляет техническими заданиями и этапами клиентских работ, но CRUD
предметных сущностей ещё не стабилизирован. AI-инструмент должен приносить
пользу сейчас, не зависеть от незавершённого API и не изменять данные основного
проекта. По условию облачным провайдером должен быть GigaChat API, а выбор
провайдера должен меняться через `.env`.

## Рассмотренные варианты

1. Tool для прямого создания задач в WorkTrack. Он дал бы более короткий
   пользовательский сценарий, но преждевременно зафиксировал бы отсутствующий
   HTTP-контракт и мог бы создавать некорректные записи.
2. Tool для проверки качества постановки до записи. Он работает автономно,
   даёт детерминированный результат и позже встраивается перед командой create.
3. Только LLM-промпт без Tool. Такой вариант короче, но результат нельзя
   стабильно тестировать, а критерии меняются вместе с формулировкой модели.

## Решение

Реализовать детерминированный `assess_work_item`, принимающий одну JSON-строку
и всегда возвращающий JSON. LLM отвечает за перевод свободного текста в
структуру и объяснение результата, а Tool — за правила готовности и стабильные
коды замечаний.

GigaChat подключается адаптером `GigaChatCrewLLM`: CrewAI получает свой
`BaseLLM`, а транспорт и нативный function calling выполняет официальный
`langchain-gigachat`. Секрет хранится только в `GIGACHAT_CREDENTIALS` и имеет
тип `SecretStr`.

## Последствия

Плюсы: правила тестируются без LLM и сети; агент полезен до появления CRUD;
секрет не попадает в код; провайдер переключается без изменения Python-файлов.

Минусы: эвристики не понимают предметный контекст так глубоко, как человек;
нужно синхронизировать словари и обязательные поля с будущей моделью WorkTrack;
кастомный адаптер придётся проверять при обновлении CrewAI и GigaChat SDK.

## Наблюдения из трассы

Трасса считается доказательной только если содержит событие `tool_called` между
`run_started` и `run_completed`. Локальные unit-тесты не заменяют реальный
прогон GigaChat. Реальная трасса добавляется после предоставления персонального
ключа API.

## Когда пересмотреть

- в WorkTrack появился стабильный endpoint создания и валидации задач;
- обязательные поля или статусы задач изменились;
- CrewAI получил официальный GigaChat provider;
- GigaChat изменил формат function calling.
